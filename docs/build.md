# Build Guide

This repository builds LibreELEC images through `scripts/image` and the top-level `Makefile` targets.

## Host Requirements

- Linux build host (native Linux recommended)
- `bash`, `make`, `git`, and standard GNU build utilities in `PATH`
- Internet access to download upstream sources
- Enough free disk space for build trees and output artifacts (tens of GB recommended)
- Enough RAM/CPU for parallel compilation (more cores significantly reduce build time)

If you report build failures, ensure you reproduce from a clean tree and after a clean build step.

## Quickstart

```bash
# from repository root
PROJECT=RPi DEVICE=RPi4 ARCH=arm make release
```

Adjust `PROJECT` and `DEVICE` to match your hardware family.

Build outputs are written to `target/`.

## Make Targets

- `make` or `make release`: build release artifacts and package release tarballs
- `make image`: run image generation flow (`mkimage`)
- `make noobs`: create NOOBS-flavored release artifacts
- `make clean`: remove build output via `scripts/makefile_helper --clean`
- `make distclean`: deeper cleanup via `scripts/makefile_helper --distclean`
- `make src-pkg`: create `sources.tar.xz` from `sources/`

## Common Build Variables

The build scripts consume values from `config/options` and environment variables. Common overrides:

- `PROJECT`: hardware/project family to build
- `DEVICE`: specific device inside a project (when applicable)
- `ARCH`: target architecture override
- `CUSTOM_VERSION`: override generated distro version string
- `CUSTOM_IMAGE_NAME`: override default image naming
- `IMAGE_SUFFIX`: append suffix to generated image name
- `UBOOT_SYSTEM`: select specific u-boot board variant where supported

Example:

```bash
PROJECT=RPi DEVICE=RPi4 CUSTOM_VERSION=12.0-test IMAGE_SUFFIX=local make release
```

## Output Artifacts

Successful release builds generally emit:

- release tarball(s) in `target/`
- checksum files (`.sha256`)
- intermediate `SYSTEM` and `KERNEL` artifacts staged during packaging

Exact file names include project/device and version metadata generated by `scripts/image`.

## Troubleshooting Basics

- Start with `make clean` before retrying a failed build.
- Confirm the repository is up to date and your branch is clean.
- Check command output for the first real failure (later errors are often cascading).
- Validate custom version/name overrides if produced files are unexpectedly named.
- Re-run with minimal overrides to isolate config-related issues.
